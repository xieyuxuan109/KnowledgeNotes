### 组件注册
```
@Configuration、@SpringBootConfiguration
@Bean、@Scope
@Controller、@Service、@Repository、@Component
@Import
@ComponentScan
```
```
步骤：
1、@Configuration 编写一个配置类(它的作用就是告诉 Spring 的 IoC 容器：“这个类是一个配置类，里面定义了一系列创建 Bean 的规则，相当于以前老项目里那个 applicationContext.xml 配置文件。”)
2、在配置类中，自定义方法给容器中注册组件。配合@Bean(告诉 IoC 容器：“请你帮我创建这个对象，并把它放进你的仓库里（让我以后能随时取用）。”) 组件在容器中的名字为方法名
3、或使用@Import 导入第三方的组件
```
```
@Configuration
public class Config {
    @Bean("cat02") //这样是修改名子
    public Cat cat01() {
        Cat cat = new Cat();
        cat.setName("小猫");
        cat.setAge(1);
        return cat;
    }
}
```

### Bean的作用域 @Scope("prototype")
```
1. 单实例（Singleton）
概念：在整个 Spring IoC 容器中，某个 Bean 定义只存在一个共享的实例。
行为：无论你通过 getBean() 获取多少次，或者在其他地方通过 @Autowired 注入多少次，拿到的永远是同一个对象（内存地址相同）。
默认规则：在 Spring 中，Bean 默认就是单例的。 你之前看到的那些打印出来的 Bean（如 helloController、jacksonObjectMapper 等），如果没有特别指定，全都是单实例。
适用场景：无状态的 Bean（比如 Controller、Service、Dao 层组件）。因为它们不保存用户的会话数据，共享一个实例可以节省内存，提高性能。
```
```
2. 多实例（Prototype / 原型模式）
概念：每次向 Spring 容器请求该 Bean 时，容器都会创建一个全新的实例。
行为：如果你请求 3 次，Spring 就会在内存中创建 3 个独立的对象，它们互不干扰。
适用场景：有状态的 Bean。比如某些需要保存临时状态、用户会话数据或者每次使用都需要独立数据的对象。
```
### 什么是loC容器
```
loC 容器在 Spring Boot 中最核心、最简洁的作用可以总结为 “管生、管配、管用”：
管生（接管对象的创建）：不需要你在代码里手动写 new 去实例化对象。你只要在类上添加 @Component、@Service 等注解（如截图中所示），或者在配置类里写 @Bean，容器启动时就会自动帮你把这些对象（Bean）创建好。
管配（自动依赖装配）：当A对象需要用到B对象时，你不需要自己去 new 一个 B。只要在A里写上 @Autowired，容器就会自动从它的“仓库”里把合适的 B 对象注入给 A。这让代码极度解耦。
管用（管理生命周期）：容器会统一管理对象的生存周期，比如决定它是单例（整个程序只有一个实例）还是多例，以及在程序关闭时怎么销毁它。
```
```
一句话大白话总结：
IoC 容器就像是一个中央大仓库。你（开发者）只需要告诉仓库“我要什么零件”（写注解），仓库就会自动帮你把零件制造出来、装好内部的螺丝，并在你需要用到的时候直接递到你手上，你只管安心写业务逻辑即可。
```
### 条件注册
```
@ConditionalOnClass：如果类路径中存在这个类，则触发指定行为
@ConditionalOnMissingClass：如果类路径中不存在这个类，则触发指定行为
@ConditionalOnBean：如果容器中存在这个 Bean（组件），则触发指定行为
@ConditionalOnMissingBean：如果容器中不存在这个 Bean（组件），则触发指定行为
```
